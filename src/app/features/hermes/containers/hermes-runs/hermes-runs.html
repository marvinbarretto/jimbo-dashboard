Every Hermes cron tick is recorded in system_events. This page classifies each agent.end into an outcome bucket so you can see which crons are healthy, which are hitting quotas, and which are silently writing prose instead of completing dispatches.

Most jobs now run on a flat-rate subscription, so their cost is £0 by definition and tokens are the scarce resource — they are what a subscription cap actually consumes. Sort by tokens to see what to do less of; the metered badge marks the jobs still spending real money. Mark a verdict to record the call.

Answered is the axis that actually decides keep or cut — a job can be healthy, cheap and completely ignored. It counts only deliveries that asked for something, so a blog post or a status pulse shows — rather than a rate it was never on. That blank is deliberate: no data is not the same fact as nobody answered.
