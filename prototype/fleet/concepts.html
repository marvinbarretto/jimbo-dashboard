Fleet redesign Three directions, one shared fixture. Nothing here touches production code.

Three ways to rebuild /fleet

The page today is nine flat sections in one scroll — Right now, Needs attention, Machines, Workers, Queue, Lanes, Burn, Folds, Recent completions — each rendered at the same weight, so a dead machine and a fold cadence table compete equally for the eye. It answers "what is in GET /api/dispatch/stats?" rather than "is the fleet healthy, and if not, what do I do about it?"

All three directions below keep every judgement the current page fought for, and differ only in what they organise by. Each runs on the same fixture, with a calm/incident switch top-right, because a monitoring redesign judged only on the all-green case tells you nothing.

Direction A
Console
organised by the question you arrived with
An always-on actor strip — who is doing what, right now — over five tabs, each one a question: Anything broken? · Who is doing what? · What is queued? · What is it costing? · What happened? Each tab carries a right-hand rail with the knobs that question makes you reach for. The verdict line, the actor strip and the fault counts never hide inside a tab. Best when you arrive knowing what you want. The valve rail turns the page from a readout into a control surface.
Open A →
Direction B
Timeline
organised by time
One swimlane per actor over a trailing window, each labelled with what that actor is doing this second. Dispatches are blocks, reporting is a bar, silence is a shaded band, and the queue sits in a gutter to the right of now — work drawn in the future. Best for the diagnosis. Three lanes stopping at the same vertical is a machine, and you read it off the shape before you read a word.
Open B →
Direction C
Triage
organised by the answer, in words
One written page: a verdict paragraph, the cast listed one actor per line, then five questions answered in prose with their evidence folded up underneath. Serif reading register for the answers, sans scanning register for the tables — the switch between registers is the hierarchy, so there is no second colour system. Best for the ten-times-a-day glance, and the only one of the three that survives a phone.
Open C →

They are not mutually exclusive. C's verdict paragraph is the natural top of A; B is a plausible sixth tab of A rather than a whole page. My recommendation: C's lede + A's tabs, with B as the "What happened?" tab — but the point of three files is that you can disagree by clicking.

The fleet is a cast, not a rack

The current page leads with Machines, then Workers — infrastructure first, and the same fact stated twice. But a machine matters exactly twice: when it explains a silence, and when you need to go and restart it. Both of those are facts about an actor, so all three directions demote the box to an attribute on the actor's row and let it surface only when it becomes the diagnosis.

  • The cast is six, not four. boris, jeffrey, steward, kipper, plus hermes on the VPS — and marvin. The proposal queue is Marvin's lane, and drawing it as a property of boris blames a worker that is polling perfectly normally.
  • Every actor states its current action first. Not its status enum — the verb and the thing: running code/doc-refresh — "doc:auth", 3m in.
  • "Nothing is running" is the normal case, and useless alone. A dispatch is one to five minutes of work, so the live list is empty most of the time. Every actor therefore carries its current action and the last thing it shipped — which is the pair that separates idle-between-jobs from stopped. This is the single biggest thing the fixture exposed.
  • Ordering is by activity. Live work first, then whoever shipped most recently. Ambient hermes and the human sort to the back unless something is wrong with them.

Do we need new primitives?

Mostly no — and that is the finding. The current /fleet hand-rolls <table class="fleet__table"> four times, its own .fleet-worker__dot, its own stat grid and its own spark strip, while eleven shared components already cover those jobs. Two things are genuinely missing, and both are named below.

RegionVerdictComponent, or spec if new
Verdict bannernew app-ui-verdict-bar — tone, headline, evidence line, meta slot. Nothing existing states a roll-up judgement with its evidence: notification-bar interrupts, lifecycle-banner is per-item and takes a fixed state set. Small, and used by all three directions.
Fault listextend ui-readiness-panel is already checks with an ok flag and a blocker string, which is exactly this shape. Needs a tone beyond ok/blocked (warn vs alert vs "yours"), and an actions slot per row.
Tabs (A)reuse ui-inline-tabs — already takes value/label/count/dotColor. The count badge wants a tone.
Actor row / cardreuse ui-card + actor-chip / actor-avatar. The per-actor colours are already tokens (--actor-color-*) and the fleet page uses none of them — every worker on it renders identically grey.
"Right now" stripnew app-actor-now-strip — one cell per actor: current verb, what it is on, and what it last shipped. Thin, but it is the component that answers the question the page is actually opened with, and it belongs on the journal and the daily report too.
Status dots & pillsreuse ui-badge, dispatch-status-badge, job-chip. The hand-rolled .fleet-worker__dot--{tone} can go.

Its own doc comment draws the distinction the fleet page gets backwards: a stat card states a fact, ui-metric states a measurement — and it already carries a baseline, a delta and a sparkline. "$7.81 over five hours" is precisely a measurement with no baseline.

Flow filterreuse ui-filter-pills — the current page already uses it; it just wants a colour dot per option.
Folded evidence (C)reuse ui-section with collapsible, and ui-prose for the reading register.
Swimlanes (B)new app-ui-swimlane-chart — lanes × a time window; spans, instants, shaded gaps, a now-line and an optional future gutter. The only substantial new component here, and it earns its place beyond this page: the same chart draws the journal's day stream and the retro timeline.
The verdict engine already exists, and /fleet does not use it. src/app/features/journal/utils/fleet-health.ts holds workerRows(), healthAlerts(), backlogReason() and healthHeadline() — every judgement above, tested, with the reasoning written down. The journal widget consumes it. /fleet hand-rolls its own heartbeatTone() and queueVerdict() instead, so the two surfaces can disagree about the same fleet. Whichever direction wins, step one is hoisting that module out of features/journal/utils/ into a shared domain service and pointing both at it. The prototypes here run on a JS port of it, which is how they get their verdict lines for free.

What the API cannot currently answer

  • No heartbeat history. workers[].checked_at is one instant. B can draw silence truthfully (it starts at the last beat) but has to assume continuity before it. Wants GET /api/dispatch/heartbeats?since=.
  • No pump tick history. Same shape — last_pipeline_enqueue_at is a single instant, so B extrapolates the earlier ticks at the 30-minute cadence.
  • No per-fold expected cadence. The 3-day staleness threshold is hard-coded in the component. A fold that legitimately runs weekly would read as broken.
  • Actions are all read-only today. Every button in A and C is drawn but inert. Retry, reap, release-lock and kick-pump need endpoints; the valve knobs would go through the existing settings write path (state_set_valve).
  • The valves are already there and nothing renders them. GET /api/state/pipeline returns 17 keyed, labelled controls with their values and an is_default flag — including pipeline.deepread_items_per_tick = 0, which is the actual answer to "why does groom ship nothing". A's rail is the first thing to draw them.

Fixture

data.js holds a real production snapshot (2026-09-08T14:51Z) plus a reconstructed incident: m2 drops, its three workers go silent with it, 27 approved jobs jam behind them, the pump stops, a fold dies quietly, and kipper stays fine throughout — which is the case that separates a page that attributes faults from one that just counts them. Every instant is stored as an offset and rebuilt at load, so the calm state still looks calm whenever you open this.
