Journal IA — Overview as the story layer

Wireframe set · desktop 1280 · structure and intent only

Persona
Marvin, mid-afternoon or end of day, opening /journal/overview/day/<today>. He is not reconstructing anything — he wants to know what today amounts to.
Job
Read the day's story through data in ~15 seconds: is this a normal day, a good day, or a day that quietly went nowhere — and where do I click to find out why.
Entry
Life → Journal → Overview (default landing). Also arrived at from a Telegram briefing link.
Exit
Either satisfied and gone, or drilled into Work / Body / Jimbo, or opened Evening to log what the machine can't see.
Viewport
Desktop, 1280px frame. Mobile shell (/m) is a separate surface, out of scope here.
The premise being tested
  • Overview currently shows counters. A counter with no baseline is not a story — "FOCUS 0m" at 17:55 only means something against "you normally have 95m by now".
  • So: every headline number on Overview carries context — vs yesterday, vs the 7-day median for that weekday, and a cumulative day/week figure.
  • Overview stays work-first. Personal data supports at subordinate weight and links out.
  • No generated prose at the top. The shape of the data is the narrative; the written day report stays available but collapsed, below the evidence.

The split

01 · Overview (day) — the story layer REBUILT

Metric rail (context-carrying) → the day's shape (cumulative vs typical) → work realised (bullets) → personal strip → Jimbo strip → day report, collapsed.

Gains: cumulative chart, deltas everywhere, outcome bullets. Loses: raw counter tiles, the half-page fuel/macros block, the checks panel, the lane timeline.

02 · WorkMOSTLY AS-IS

Already the deepest tab. Receives the lane timeline from Overview. Desk-by-hour bars gain a 7-day median ghost so the shape is comparable.

03 · BodyRECEIVES

Receives the whole fuel & training block currently occupying Overview: protein meters, macros donut, gym sets/volume.

04 · JimboEXTENDED

Agent runs, spend, failure rate. Overview shows one strip; this is where cost per skill and the failure detail live.

05 · EveningRECEIVES

Receives the day-checks authoring panel. Authoring belongs in a reflection flow, not on a read-only glance page.

06 · Metric anatomy — the primitive being proposed NEW

Every variant of ui-metric / ui-delta in one place: positive, negative, inverted (YouTube up is bad), no-comparison, cumulative, zero.

Primitives this flow implies

NEW ui-metric — big numeral + label + delta stack + sparkline. The tile that replaces the counter.
NEW ui-delta — the "▲ +3 vs yest" atom. Standalone so bullets and table rows reuse it. Owns sign, direction and inversion.
NEW ui-sparkline — 8-point inline trend. Hand-rolled SVG, not Chart.js: a 5-tile rail would otherwise spin up 5 canvases.
NEW ui-cumulative-chart — today's accreting line against a ghost band of the typical day. The one chart that answers "so far today".
UPDATE ui-stat-card — narrowed, not restyled. It currently does two jobs; metrics move to ui-metric, it keeps the text-fact job (vault detail, nutrition totals). Drops its ::ng-deep flex patch.
UPDATE ui-bar-chart — optional [baseline] ghost dataset, sibling to the existing showTrend.
REUSE ui-period-totals — already rolls daily totals to day/week/month with pace-scaled targets. Likely the vehicle for cumulative figures rather than new code.
REUSE ui-progress-meter — already has pace + compareLabel/compareValue. It is already the pattern; the rest of the page is catching up to it.
Open questions — decisions for Marvin
  • Baseline definition. "vs 7d ago" — same weekday a week back, or the median of the last 7 days? A Tuesday against a Saturday is a meaningless comparison. Proposal: median of the last 4 same-weekdays for the ghost, literal yesterday for the day delta. Needs a call.
  • Data cost. Deltas need a trailing window. /api/journal/work?since=&until= already takes an arbitrary range, so no new endpoint — but Overview goes from one day-fetch to a day-fetch plus a 28-day rollup. Acceptable, or do we want a server-side /api/journal/overview that returns the comparisons pre-computed?
  • What counts as "work realised". Commits are cheap to count and weak as an outcome. Do vault items moving to done outrank commits in the bullet list? Currently sketched as: vault items first, then commits grouped by project.
  • Does the day report survive? It is genuinely good prose, but "story through data, not narrative" argues against it leading. Sketched as collapsed-at-the-bottom. Could equally move to Evening.
  • Zero-state honesty. On a 0-focus day the page should read as unusual, not empty. See the alternate states on screen 01.
